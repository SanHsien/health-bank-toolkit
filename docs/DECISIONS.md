# 設計決策

## 只用 Python 標準庫

解析的是含個資的健康資料，依賴越少，供應鏈風險與審查面越小，也容易確認程式不做任何網路呼叫。代價是 HTML 解析用 `html.parser`，不如第三方套件方便。因此 Dependabot 只管 GitHub Actions，依賴新鮮度檢查以 `fleet-waiver: freshness` 豁免（沒有宣告下限可比對）。

## 輸出資料夾在 git 工作樹內預設拒絕執行

防止脫敏結果被誤提交。要放行必須明確加上 `--allow-in-repo`，且測試涵蓋此旗標。

## 脫敏規則只能變嚴

放寬規則的風險（洩漏個資）遠大於漏遮的修補成本，所以每次修改先寫反例測試。

## 範本不下診斷、不調整藥物

儀表板與 PDF 提示詞一律要求醫療免責聲明，不下診斷、不建議調整藥物。

### 2026-11-02：保留一般性健康建議，加入固定安全提醒

維護者決定：PDF 報告保留一般性健康建議（2026-10-24 要求的「分析與建議」維持）。`AGENTS.md` 鐵律 3 的措辭改為「不下診斷、不建議調整藥物」，消除原標題「不提供醫療建議」與範本的張力；範本另加兩句逐字固定、不依個人資料產生的安全提醒：「出現急性或明顯惡化的症狀時，請立即就醫或撥打 119。」「已在使用的藥物不要自行停用，任何用藥或治療調整都要先問醫師。」。
