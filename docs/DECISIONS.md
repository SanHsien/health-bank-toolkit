# 設計決策

## 只用 Python 標準庫

解析的是含個資的健康資料，依賴越少，供應鏈風險與審查面越小，也容易確認程式不做任何網路呼叫。代價是 HTML 解析用 `html.parser`，不如第三方套件方便。因此 Dependabot 只管 GitHub Actions，依賴新鮮度檢查以 `fleet-waiver: freshness` 豁免（沒有宣告下限可比對）。

## 輸出資料夾在 git 工作樹內預設拒絕執行

防止脫敏結果被誤提交。要放行必須明確加上 `--allow-in-repo`，且測試涵蓋此旗標。

## 脫敏規則只能變嚴

放寬規則的風險（洩漏個資）遠大於漏遮的修補成本，所以每次修改先寫反例測試。

## 範本不下診斷、不調整藥物

儀表板與 PDF 提示詞一律要求醫療免責聲明。不提供醫療建議（含一般性健康建議），不下診斷、不建議調整藥物。

### 2026-11-02：PDF 報告不輸出一般性健康建議

依維護者授權採保守做法：PDF 報告只整理既有資料、呈現原始參考值與趨勢，並協助準備回診問題。不要求 AI 套用外部臨床標準評估個人風險，也不產出生活、監測、追蹤頻率、疫苗或用藥建議及個人化就醫警訊。

理由：原範本將「一般性健康建議」延伸為個人化處置建議，與鐵律 3 不一致；保留免責聲明不能消除這個衝突。限制輸出範圍可保留資料整理用途，且日後可透過範本修訂回復。

重看條件：僅在維護者明確修訂鐵律 3，並完成醫療專業審查、界定可允許的建議範圍與驗收方式後重新評估；現階段維持上述限制。

補記（同日）：維護者明確決定在範本加入固定安全句：「出現急性或明顯惡化的症狀時，請立即就醫或撥打 119。」「已在使用的藥物不要自行停用，任何用藥或治療調整都要先問醫師。」。理由：移除「需要立刻就醫的警訊」表與「勿自行中斷用藥」提醒可能降低安全。這反轉了 2026-10-24「加入分析與建議」要求中的建議部分，但保留固定安全提醒；這兩句逐字固定、不依個人資料產生，不是一般性健康建議。重看條件不變。`docs/health-bank-export-format.md` 同步改為相同限制。
